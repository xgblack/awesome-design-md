# Design Atlas

`awesome-design-md` 的独立规范浏览应用。使用 Vue 3、TypeScript 和 **Vite 8**，延续 A「浅色图库工作台」设计。无需后端或账号。

## 本轮范围

- 从 `../design-md/*/DESIGN.md` 扫描全量目录；不依赖 README 是否完整，也不以 YAML 是否可解析决定收录。
- 品牌名 / 中文关键词搜索，视觉气质、明暗、参考场景、色彩、密度、领域分类筛选，排序与逐项清除。
- 当前浏览器收藏；无法持久化时明确提示，不承诺跨设备同步。
- 详情、完整 Markdown 阅读、原样源码、复制全文、下载原文，加载错误与重试。
- 最多三份规范信息对照；手机上切换单个候选，不压缩为不可读的窄列。
- URL 恢复筛选、详情视图、排序和对照候选，支持浏览器前进 / 后退。

**具体风格的示例页面尚未制作。** 图库展示的是明确标注的规范封面，不是截图。“已有预览”为 0；详情中的设备预览不可操作。规范信息对照不等同于真实页面的视觉对比。

## 运行

Node.js 20.19+ 或 22.12+（推荐当前维护版本）。在本目录执行：

```sh
npm ci
npm run dev
```

开发服务默认只监听本机。端口被其他项目占用时，例如：

```sh
npm run dev -- --port 5178 --strictPort
```

生产构建与预览：

```sh
npm run build
npm run preview
```

部署 `dist/` 到任意静态托管服务。资源采用相对路径、路由采用 Hash，无需服务端路由回退，支持子目录部署。请完整上传 Markdown 和字体资源；不要只上传 `index.html`。从仓库根目录执行可使用 `npm --prefix preview-app run build`。

## 原规范与补充资料

原文唯一维护源仍是仓库的 `design-md/`。Vite 将原始 Markdown 作为静态资源输出，用户打开规范时才请求完整内容，图库不会同时加载全部原文。

`src/data/curation.ts` 只维护中文简介、名称和参考标签，依据每份原规范人工整理，不直接照搬根 README 的摘要。色值为原文首次出现的若干十六进制色彩摘录，**不是完整色板、颜色角色或主题判断**。新增原规范即使尚未整理，也会进入图库，显示“资料待整理”；未标注项不会假装匹配具体标签。

同一维度多选为“或”，不同维度与关键词为“且”。“推荐顺序”只是显式维护的浏览顺序，不代表质量排名；不使用文件系统修改时间伪造“最近更新”。

Markdown 阅读关闭原始 HTML 执行，不加载文档引用的远程图片，仅显示图片文字；外链仅允许 HTTP(S)，在新标签打开并隔离来源。源码、复制和下载仍保留完整原文（包括元数据）。

上游新增 / 修改规范后重新构建；开发服务会重新扫描。删除或重命名的旧详情链接会明确显示未找到，不自动映射到另一个风格。`npm run check:catalog` 会提示新增待整理项和失去原文关联的补充资料。

## 验证

```sh
npm run typecheck
npm test
npm run check:catalog
npm run build
```

自动测试覆盖目录完整性、异常头部、新增 / 修改 / 重命名文档、筛选逻辑、URL、收藏失败、原文获取失败、剪贴板失败及 Markdown 注入边界。浏览器检查另覆盖交互、下载和响应式布局；模拟手机视口不等于真机测试。

## 素材与后续扩展

外层英文字体通过 Fontsource 随应用打包：Inter、Space Grotesk，均为 OFL-1.1（许可证随 npm 包保留）。中文使用系统字体回退，不依赖在线字体服务。外层图标和规范封面为项目内 SVG/CSS；不使用品牌商标图或商业字体冒充官方素材。

未来独立示例的组织约定见 `examples/README.md`。不要把本应用的规范封面注册为已完成的页面预览。
