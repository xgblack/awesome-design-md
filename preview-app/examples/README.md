# 独立风格示例

目录名与实际 `design-md/<slug>/DESIGN.md` 对应；源规范始终是唯一原文来源，不在这里维护副本。每页在原规范擅长的主题内选择合适场景；同类主题大体相近，但文案、结构和素材可不同，不套统一业务模板，也不任意改成无关产品。

## 组成

- `index.html` / `style.css` / `main.ts`：独立文档、视觉与真实本地交互。
- `example.json`：虚构题材、实际特征、能力、素材/字体来源和具体取舍。
- `example.spec.ts`：至少两项核心操作及相关失败/边界检查；两项操作可以属于同一种能力。
- `thumbnail.webp`：由真实桌面首屏截图生成，不能手画占位图。
- `assets/`：只有需要独有资源时才存在。公共资源和非视觉通知在 `_shared/`。

制作契约、合法标签 ID 与就绪消息见 [_shared/CONTRACT.md](_shared/CONTRACT.md)，完整词表与解释以应用 `src/data/facets.ts` 为准。

## 制作与验收

1. 读对应规范与知识库的修订设计矩阵，先确认主题与产品任务匹配；采用具体组件规定，记录源文矛盾与替代。
2. 在本页目录实现，不改原规范或其他页面；字体/资源只用本地、许可可分发内容。
3. 使用明确的本地固定数据与内存状态，不假装注册、支付、实时行情、生成或发信；媒体若播放，必须来自真实音视频事件。
4. 绑定交互后调用 `announceReady(slug)`。这是单个文档的运行就绪状态，**不等于制作验收**。父工作台验证窗口、来源、slug 和实例编号，404 回退或过期消息不能冒充就绪。
5. 用例、桌面/手机/320px检查、实际截图和视觉核对都完成后，维护者才将元数据状态置为 `ready` 并填写 `viewports`。仅有文件、media query 或 HTTP 200 都不是验收证据。

新上游风格没有示例时仍收录为 pending；坏示例元数据会显示诊断并保持待制作，不拖垮其他条目。`vp run check:examples` 检查关联、资源、词表及必要文件；原规范删除/重命名造成孤儿时需要显式处理。

## 资源路径与构建

Vite 的多 HTML 入口在一次构建中编译所有页面。HTML/CSS 的静态引用由 Vite 重写；TypeScript 切换图片/媒体必须使用显式导入 URL 或可静态分析的 `new URL(..., import.meta.url)`，不能拼 `./assets/` 字符串，依赖仅在开发服务器存在的路径。

JS 里的用户文字按文本呈现；终端、查询和代码输入不会被执行。独立打开和 iframe 内使用同一份页面，不能接触 parent DOM、父路由、外层收藏存储或远程业务 API。

两端截图保存在被忽略的 `.screenshots/examples/`；运行必需的缩略图随源码保留。修改页面后重新运行对应操作测试、截图并重建，不新增截图哈希冻结、审批基线或第二套规范源。
